# AI / CS Research Engineer Curriculum — v1.4 Executable Architecture

v1.4 preserves the full 153-course knowledge library but no longer treats it as one mandatory linear sequence.

## Three execution tiers

### Tier 1 — Applied AI / KSP Engineer
- 35 course entries / selected-unit slices
- 1,755 planned path hours
- Goal: productive Linux/Python/platform/security/ML/RAG/agent/MCP/KSP engineering
- Exit evidence: reproducible platform stack, secure software/supply-chain evidence, evaluated RAG system, agent/MCP tool-policy tests, and external/verifiable artifacts

### Tier 2 — ML / AI Systems Engineer
- Defined core plus specialization bundles
- Approximately 2,285 incremental nominal core hours after Tier-1 credit
- Goal: model training, inference, evaluation, GPU systems, post-training and distillation
- Specializations: math/statistics/ML, systems, platform/FDE, security, deep learning, GPU/inference, post-training/distillation, retrieval/agents/niche AI, multimodal/robotics/AI4Science

### Tier 3 — Research Engineer
- Research core plus advanced-theory/frontier electives
- Approximately 2,205 nominal research-core hours
- Goal: paper reproduction, rigorous ablations, independent research judgment and research-grade capstones
- Pass standard: >=90% plus an original extension, ablation, stress test or defensible negative result

## Typed prerequisites
Every direct prerequisite edge is classified as:
- **HARD** — must be demonstrated before course start
- **SOFT** — recommended before or concurrently; not a blocker
- **JIT** — learn the needed concept immediately before the relevant lab
- **ENRICHMENT** — improves depth/research quality but must not delay productive applied work

Only HARD edges gate starting a course.

## Mastery protocol
Each course is scored on five equally weighted criteria:
1. conceptual understanding
2. implementation / reconstruction
3. diagnosis / debugging
4. benchmark / evaluation quality
5. defense / reproducibility

Tier 1/2 pass: >=80% overall with no critical criterion failed. Tier 3: >=90% plus an original extension/ablation.

**Mastery loop:** Build → Break → Diagnose → REA/Reconstruct → Benchmark → Improve → Defend.

REA means **Reverse Engineering & Analysis**: inspect architecture, dependencies, interfaces, runtime behavior and failure modes; reconstruct or modify the system; then defend the evidence.

## Workload and review cadence
- Original full-library nominal total retained: 10,930 hours
- v1.4 adds a planning-high estimate rather than pretending the nominal total is a precise calendar
- Actual learner hours must be recorded and the active path reviewed every 12 weeks

## Compute governance
GPU-requiring courses now carry a GPU tier, estimated GPU hours, planning cost, scaled-down alternative and budget guardrail. Planning rates are assumptions for budgeting only, not vendor quotes.

## Resource governance
- Papers With Code is no longer a curriculum dependency
- Prefer official university/vendor/open-source sources, Hugging Face evaluation/leaderboard resources, arXiv, OpenReview, ReScience C, and author/source repositories
- Generic track-wide repo stacks are reference material, not automatic course requirements
- Run an automated link check as a release gate and record last-verified dates

## Distillation
All 17 distillation/niche lanes now have nominal lab hours and required/elective status. They are specialization labs under AI-842 / AI-860 and are counted only when activated.

The pharmacology specialist system is an approved longitudinal niche-AI/distillation case study.

## Canonical artifacts
The editable workbook and clickable PDF are archived in the user's Google Drive curriculum catalog. GitHub mirrors the public/version-controlled curriculum logic rather than storing private Drive artifacts.
